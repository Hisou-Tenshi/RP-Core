# 公开逻辑与私密数据边界

公开仓拥有所有执行逻辑和非私密设置。默认 run 命令只把私密仓当数据源，不导入模块、不执行私密命令。角色卡中的自然语言是数据，不能注册任意 Python 代码。新驱动和修复在公开仓发布，所有角色共用。

## 数据与凭证

- 角色卡、身份、聊天、记忆、笔记、附件、日志与运行状态留在私密仓。
- 模型名、厂商端点、路由、预算和平台设置在公开配置；敏感端点可引用环境变量的驱动扩展，不能把实际密钥提交进去。
- 每个角色使用独立 GitHub Environment，凭证用单独 Secrets 注入；0.2 不再要求大 JSON secret。
- 运行器只输出计数或安全错误。没有运行数据 artifact、Release、Step Summary 或实例 cache。
- webhook 消息先持久化到私密 inbox，公开 dispatch 只带不透明事件 ID。
- PR CI 仅运行合成数据；带凭证的角色任务只接受默认分支的受信配置。

## 实现检查

- 固定 Actions 提交与锁定 Python 依赖；公开 I/O Schema 校验与路径边界检查。
- 数据 I/O 只允许内置 driver、文件映射、会话映射；禁止私密可执行 manifest。
- HTTP 只允许 HTTPS（测试使用 loopback HTTP），拒绝带 URL 凭证，禁止重定向转发认证头。
- 标准接口限制帧大小、超时并校验响应 ID；不转发原始异常或模型错误正文。
- 生成阶段不提前修改日记或发送消息；原子事务保存回执、写入和待发操作。
- 旧格式测试检查原行、未知字段、向量与 embedding 缓存保留；不引入真实对话 fixture。

0.1 的可选 stdio 扩展接口为受信任进程接口，并非沙箱。默认多角色工作流不走私密进程模式。

自动审查不是完整渗透测试或零泄露保证。模型结构校验不等于完整内容审核。平台缺乏幂等发送时可能重发；Git 二进制冲突不会自动丢弃任一方。现有兼容驱动不是原 Tenshi 全量功能的复制。
