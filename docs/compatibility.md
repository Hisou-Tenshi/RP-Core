# 协议兼容承诺

包版本与协议版本分开。rp/1 的承诺是：

1. 不移除既有方法、必填字段或既有枚举值，不改变其语义。
2. 新可选字段可添加；双方忽略未知可选字段。
3. 新方法、新能力先通过 capabilities/bridge.describe 协商，不能让现有适配器被迫实现。
4. 破坏性变化采用新主版本；旧适配器在协商时明确失败，不能静默误读。
5. 已发布的 rp/1 schema、合成 fixture 与契约测试作为回归基线。

私密端可独立修改角色、存储格式、模型厂商、密钥、平台字段与工具实现。使用 extensions 和私密 deferred 工具增加平台能力；核心不解释私密命名空间。

这不是对永远不修改公开代码的保证。全新的核心编排能力可能需要升级；已有集成不应因实例字段、路径或厂商变化而返修公开核心。

事件 ID 与规范请求摘要共同定义一次操作。重试需保持规范事件与维护参数相同；不能给同一 ID 增加不同的业务信息。核心不会在冲突后自动重跑模型。
