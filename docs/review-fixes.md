# 2026-11-15 审查修复

本次修改公开执行框架与合成回归；没有修改角色卡、已有数据库、模型目录、Secrets 或生产消息。

| 问题 | 修复后的行为 |
| --- | --- |
| R1 假成功回执 | 回复进程写原子结果文件；日志锁失败可重试，发送失败、缺失结果、超时隔离。流式发送核验首段和所有后续气泡/贴纸；生成完成的 replied_flag 不再代替送达确认。感知层发送失败也返回非零。CLI 在处理完独立任务后，对失败/隔离返回非零。 |
| R2 队列阻塞 | 发送不明确的事件逐条隔离；probe 等无聊天发送的任务最多重试三次，旧 uncertain probe 也可以恢复。新消息和剩余维护继续执行。历史中的隔离标记同时阻止下一轮隐式重发旧消息；持久化失败仍立即停止。 |
| R3 定时丢失 | 先写私密 inbox 并完成 dispatch，再写独立 KV 消费确认。消费者不再改写共享日程快照，因此不会覆盖同时发生的日程同步。私密写入、dispatch 或消费确认失败均保留重试来源，稳定事件 ID 去重。确认 TTL 八天，日程快照 TTL 七天。 |
| R4 评估/重写写工具 | 评估、主回复重写和感知风格重写使用无工具入口；执行器还会强制检查禁用工具的上下文。降级链返回实际成功的模型/厂商，供评估继续使用，不再误记列表首项。 |
| R5 运维缺项 | 聊天整理之外补日志压缩轮转、附件保留和独立私密 Release 备份。每次清洗日志后轮转超过 10 MiB 的活动日志，日常清理轮转其余日志。保留最近三个归档日。只删除三天以前且未被当前/归档 JSON 引用的附件；引用读取失败时停止删除。 |
| R6 并发结果丢弃 | 超过 Wave1 总预算时仍取回已经完成的 future；已尝试的意图分析不会立即同步重做。移除对未定检索 query 的投机 embedding，最终 query 在检索时计算。 |
| R7 超时后台副作用 | 调用上下文传播取消和父 deadline；SDK 请求、后续请求、流式回调、Telegram 发出和工具分发检查有效性。新建 SDK 网络超时受当前剩余预算限制。Wave1/2 的线程池等待有界，底层 SDK 在取消后不能继续分发工具/后续请求。 |
| R8 Grok 仅代理 | 去掉只看顶层官方 key 的预检，交由实际构建出的通路与档位判断。空 OpenRouter 模型池也不再访问索引 0。 |
| R9 身份不一致 | 完整 tenshi-v1 引擎明确限定每个数据仓一个用户及其私人 Telegram 对话；Python 宿主和 Worker 同样拒绝多用户/不同 chat 配置。native 驱动原有多用户接口保留。 |
| R10 实例凭据 | 工作流向宿主传递选中的 RP_DATA_REPOSITORY；旧 REPO_NAME 跟随所选实例。token 按非空 RP_INSTANCE_TOKEN、旧别名及既有 token 回退，空旧变量不再覆盖有效凭据。 |

私密备份只通过框架代码调用 GitHub API：先校验目标完整仓库名与 private=true，禁止认证重定向，再生成/上传 ZIP；不会上传公开 Actions artifact。SQLite 使用 backup API 生成一致快照，不依赖复制 WAL 数据库文件。每日备份保留七个、每周保留四个，仅清理 rp-core 自己的备份 Release；同周期已确认上传的资产不重复上传。默认配置按日/周间隔运行，也可执行 full --task daily-backup / weekly-backup。需要所选私密仓的 Contents 写权限。

进一步落实的优化：embedding 缓存 miss 进行同 key single-flight，不阻塞不同文本的网络调用；批量缓存查询与批量 chat embedding 保留顺序、purpose 和失败不缓存语义；总结 RAG 与维护共用一个 MemoryManager；维护数据与账本合并为一次持久化；角色卡按路径、mtime、size、inode 缓存并返回副本；日志分块脱敏，跨块凭据也会匹配，相同凭据下未改变的文件不再重复扫描。

没有直接合并路由/意图两种模型判断，也没有关闭评估器或改变其触发策略。这些是需要样本质量对比的候选策略，不是可以由调用次数证明等价的错误修复。不同输入的向量、现有 content_hash 幂等策略和逐条记忆写入继续保留；本次不重建索引或迁移数据库。

取消的边界：已经开始的网络 I/O 或工具写入无法由 Python 线程追溯撤销。取消检查阻止的是过期工作继续产生新的动作；外层进程组硬超时仍作为最后边界。发送不明确会隔离，不能自动推断成没有送达。需要核对私密回执与 Telegram 后再手动解除对应历史标记/回执，重试上限也须显式重置。

验证使用临时数据、mock 和既有合成 shadow，不进行真实模型生成、Telegram 测试发送或生产压力测试。没有提供未经测量的提速百分比；本地通过不表示已经部署到线上。
