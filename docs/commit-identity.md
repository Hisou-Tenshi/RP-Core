# Commit identity and automated commit titles

This repository is public. It never stores a personal name or address for the
automated commits that a deployment writes into its **private** data repository.
Those values are supplied at runtime from the private repository's
`identity.json` (or from environment variables in the Cloudflare Worker case),
so the public code contains placeholders only.

## Identity classes

Automated commits fall into three identity classes:

| Class | Who it represents | Used for |
| --- | --- | --- |
| `owner` | The human operator | Manual or owner-initiated writes |
| `character` | The role-play character | Replies, perception, memory updates |
| `system` | A non-human service | Sync, maintenance, probe, keepalive jobs |

`character` is a separate GitHub account from `owner` because the character is
an actor in its own right. `system` identities have no GitHub account; they use
`*.invalid` addresses such as `tenshi-sync@tenshi.invalid`.

## Title format

Every automated commit uses one title shape:

```
<category>｜<event> · MM-DD HH:MM:SS [skip ci]
```

- `｜` is the full-width vertical bar (U+FF5C), not a plain `|`.
- `MM-DD HH:MM:SS` is **Beijing time** (`Asia/Shanghai`, UTC+8), always two
  digits per field, for example `11-16 17:50:08`.
- `[skip ci]` stays last so automated commits do not re-trigger CI.

## Category vocabulary

| Category | Meaning | Example event |
| --- | --- | --- |
| `收讯` | Inbound message | `消息已入队` (message queued) |
| `回复` | Reply | `对话与痕迹入档` (conversation archived) |
| `感知` | Perception | `世界观测日志` (world observation log) |
| `记忆` | Memory | `例行记忆更新` (routine memory update) |
| `归档` | Archive | `tenshi_log 裁切与卷宗归档` (log rotation and archive) |
| `维护` | Maintenance | `运行时日志归档` (runtime log cleanup) |
| `汇流` | Merge | `<branch> 并入 main` (staging branch merged into main) |
| `恢复` | Recovery | Recovery-state snapshot |
| `探活` | Probe | `通路健康快照` (provider health snapshot) |
| `保活` | Keepalive | `README 版权页脚更新` (README footer refresh) |

## Where the identity comes from

`identity.json` in the private data repository may carry a `git` section:

```json
{
  "git": {
    "owner":     {"name": "<owner name>",     "email": "<owner email>"},
    "character": {"name": "<character name>", "email": "<character email>"},
    "systems": {
      "sync":        {"name": "<sync name>",        "email": "<sync email>"},
      "maintenance": {"name": "<maintenance name>", "email": "<maintenance email>"},
      "probe":       {"name": "<probe name>",       "email": "<probe email>"},
      "keepalive":   {"name": "<keepalive name>",   "email": "<keepalive email>"}
    }
  }
}
```

Workflows and sync scripts pass the matching pair explicitly with
`--git-name` / `--git-email` (or the equivalent `git -c user.name/user.email`)
instead of relying on a repository default, so one commit cannot silently
inherit another actor's identity.

The runtime-side helper that renders the same shape from `identity.json` lives in
`src/rp_core/identity.py` (`stamp()` / `title()`). The compat git-sync script
keeps its own copy of the stamp formatting because it also has to run standalone
from the vendored tree; both produce identical strings.

## Cloudflare Worker writes

The Worker (`integrations/cloudflare/`) queues events into the private data
repository through three GitHub Contents API `PUT` call sites. They share two
helpers in `integrations/cloudflare/telegram.mjs`:

- `privateCommitMessage(kind)` — returns
  `收讯｜消息已入队 · MM-DD HH:MM:SS [skip ci]` in Beijing time, independent of
  the Worker runtime's local time zone. `kind` is currently `queue`; unknown
  kinds throw.
- `privateCommitIdentity(env)` — returns `{author, committer}` only when **both**
  `RP_OWNER_GIT_NAME` and `RP_OWNER_GIT_EMAIL` are set and non-blank. Otherwise
  it returns `{}`, so the `PUT` body carries no `author`/`committer` and GitHub
  attributes the commit to the token holder.

The `dashboard-worker.mjs` single-file bundle is generated by
`node scripts/build_cloudflare.mjs`; edit the source modules, then regenerate.

## Merge commits from the compat git-sync

`src/rp_core/compat_runtime/scripts/tenshi_git_sync.py` renders its merge title
from the same rules:

```
汇流｜<branch> 并入 main · MM-DD HH:MM:SS [skip ci]
```

The timestamp is formatted in Beijing time regardless of the host time zone.
The remaining merge behavior (--no-ff, conflict resolution, push and branch
cleanup) is unchanged.
